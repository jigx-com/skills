# Fixes in YAML and in TypeScript

Write every proposed fix in the solution's own language. A YAML solution (a folder
with `index.jigx`) changes `.jigx` files; a TypeScript SDK solution (`src/app.ts`,
built to `build/output.json`) changes the `src/*.ts` file the finding points at. Never
edit `build/output.json`: it is regenerated by `jigx build`. For SDK projects the audit
already maps each finding to its `src` file; the path after `›` is the path in the
built app, so find the builder call that produces it.

SDK calls below are the ones the `jigx create --from-yaml` migration emits. When a
change needs a builder option you have not seen in the project, check the `jigx` skill
(`app-architecture.md`) or the SDK types before writing it; do not guess an API.

## B · Queries and indexes

| Finding | YAML | TypeScript SDK |
| --- | --- | --- |
| `rewrite-query-shorthand` | Replace every `'$.field'` with `json_extract(data, '$.field')` in `options.query`, keep `rewriteQuery: false` | Same change inside `.query(\`…\`)`; keep `.rewriteQuery(false)` |
| `rewrite-query-on` | Write `json_extract` in full, then add `rewriteQuery: false` under `options` | Write `json_extract` in full, then add `.rewriteQuery(false)` to the `.sqlite({...})` chain |
| `unindexed-predicate` | Add `CREATE INDEX IF NOT EXISTS idx_<table>_<field> ON [<table>] (<exact predicate text>)` to the index `execute-sql` step | Add `{ statement: "CREATE INDEX IF NOT EXISTS …" }` to the `statements` of the `executeSql({...})` index step |
| `ddl-invalidates-datasources` | In the index step, `entities: [default/debug]` (a table nothing binds to), and gate each statement on its table existing | Same in `executeSql({ entities: ['default/debug'], ... })` |
| `ddl-ungated` | Add `when:` reading `sqlite_master` for the table, or list the table in `entities:` | The same `when` on the action, or the table in `entities` |
| `or-across-keys` | Split the `OR` into one `UNION` branch per key, each with a matching index, then join back for the existing tie-break | Same change inside `.query(\`…\`)`; add the missing indexes to `executeSql({...})` |
| `cte-join-no-index` | Join the table itself and move the CTE's expressions into `ON` and the select list; add the expression index if there is none; check the plan says `SEARCH` and the result is unchanged (`profile-query.py --compare`) | Same change inside `.query(\`…\`)`; the index in `executeSql({...})` |
| `order-by-unindexed` | Index exactly the sort expression | Same, in the index step's `statements` |
| `index-not-idempotent` | `CREATE INDEX IF NOT EXISTS` | Same, in the statement string |
| `execute-sql-entities` | Add `entities: [default/debug]` | Add `entities: ['default/debug']` to `executeSql({...})` |

Copy predicate text exactly from the query into the index: SQLite only uses an
expression index whose expression matches character for character, after the alias
is removed (`indexes-and-execute-sql.md`).

## After each change

- YAML: re-run the audit on the folder, then publish the copy renamed to the test
  solution with Jigx Builder.
- SDK: `jigx build`, re-run the audit on `build/output.json`, then publish with
  `jigx_debug` `create_debug_session` (`publish: true`).
- Re-time what the change targets (`run-and-track.md`) before moving to the next
  section.
